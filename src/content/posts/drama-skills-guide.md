做 AI 短剧或漫剧的人常卡在同一处：剧本、人设、分镜、图片提示词、视频提示词散在几个工具里，改一处要手动同步另外几处，人物到第二集就「长歪」了。**[Drama Skills](https://github.com/zenstory-ai/drama-skills)** 是 zenstory-ai 开源的 Agent Skill 合集，把这套流程拆成一组技能，装进 Claude Code、Codex 或其他支持 Agent Skill 规范的环境，用文件而不是界面推进项目。

它不训练模型，也不提供额度：写作、分镜和提示词由你正在用的 Agent 模型完成，只有真正生成图片、视频、配音和音乐时才调用外部接口，按供应商计费。

<!--more-->

## 一条主线，按需取段

原著分析 → 故事开发 → 分集剧本 → 资产决策 → 图片提示词 / 分镜 → 视频提示词 → 确认后生产 → 剪辑成片 → 审查。

有原著才用前两步；手上已经有单集点子或提纲，直接写剧本即可，不必为了流程完整把可选步骤补齐。静态漫剧（关键帧 + 配音）可以整段跳过视频提示词那一层。

## 文档分层，各管一层

这是整套东西最值得借的地方。一次请求只创建它真正需要的文档，不预建空文件。

- `剧本.md` 只写发生了什么：谁说了什么，谁绷紧了脸。
- `视觉设定.md` 管需要跨镜保持的造型，写成一段能原样贴进提示词的「连续性锁」，例如 `pine-green lapel service jacket`。
- `分镜.md` 写这一镜的起点、终点和运镜理由；冻结关键帧只画起点那一格。
- `图片提示词.md` 写风格帧、角色/场景/道具参考板的提示词，以及定点修改。
- `视频提示词.md` 只写起点到终点之间，模型要执行的动作。
- `剪辑单.md` 记入出点、镜序、字幕和响度。

分层是为了减少重复与冲突，换来「改得动」：调整造型时，先改视觉设定，再同步受影响的分镜与提示词；修改某一镜的动作，重点检查对应分镜与视频提示词。引用能帮助定位影响范围，但不能保证改一个文件后其他文件自动正确。

## 一致性靠引用，不靠形容词

人物到第二镜换脸，不能只靠把同一段形容词再复制一次。身份与服装先固定到视觉设定，需要图像参考的任务再明确绑定实际存在的角色图、场景图与起始帧。

「计划生成一张角色图」「已经有这张图」「这次生成确实传入了它」是三个不同状态。只有任务实际用了同一份图像参考，才有共同的视觉依据；即使如此，生成后仍要逐镜检查。

起始关键帧只表现镜头开始时的状态，视频提示词再写之后的动作。例如角色将要转身，首帧就不要已经转到一半，避免模型重复执行。缺参考图时先补图，而不是默默改成另一种生成方式。

## 花钱之前先看预览

调用生图、生视频或配音服务前，先预览这次的数量、提示词、参考图、参数与输出位置，明确确认后再执行；改了内容或参数，就重新确认。写作与分镜也会消耗编程助手的模型额度，不能把「还没生成媒体」理解成完全没有成本。

视频任务已经提交却中断时，先按供应商任务 ID 查结果，别直接重发。请求可能已经被计费，恢复旧任务与重新生产是两件事。

## 模型限制会反过来改分镜

以火山方舟的 [Doubao Seedance 2.0](https://www.volcengine.com/docs/ark/seedance-2-0) 为例，单次输出时长 4 至 15 秒，且不支持直接上传含真人人脸的参考图或视频。前者意味着超过 15 秒的连续动作要按语义和可见状态的闭合点拆镜；后者意味着真人题材要走平台的肖像便利创作流程，而不是把真人照片当 `REF-*` 挂进去。

对白也要参与分镜决策。文本估时只能当初稿，最终要听实际配音。一句台词长过目标镜时，可以拆到说话者与听者的几个镜头上，而不是强行加快语速塞进去。

## 开始用

```bash
npx skills add zenstory-ai/drama-skills -y -g
```

`-g` 是全局安装，去掉只装当前目录，更新时重跑同一条。前提：支持 Agent Skill 规范的编程 Agent、终端能跑 `npx` 的 Node、Python 3.9 以上；要剪辑成片，还得有 `ffmpeg` / `ffprobe`。Claude Code 用 `/short-drama`，Codex 用 `$short-drama`，也可以直接用自然语言说任务。

一段最小流程（示例，题材自换）：

```text
用 $short-drama 初始化一个竖屏 9:16 的短剧项目
用 $short-drama-write 写第 1 集：外卖员在高档餐厅被经理羞辱，亮出董事身份
用 $short-drama-assets 拆人物 / 场景 / 道具
用 $short-drama-storyboard 做分镜与冻结关键帧
用 $short-drama-video-prompts 逐镜翻译成视频提示词
用 $short-drama-produce 预览任务，等我确认后再执行
用 $short-drama-edit 把已生产的镜头剪成片
```

制作中先检查文档引用、镜长与参考图有没有对齐，再看成片里的脸、服装、空间和动作是否连续。交付时一起保留剧本、设定、分镜与剪辑单，后面改一镜才有落点。

## 费用与边界

生成媒体按供应商计费，自己的模型、接口与素材需要另外准备。仓库代码和文档是 MIT，但改编的作品、角色形象和生成素材不自动落在这个许可范围内，发布前要确认相应权利。

文字层面的锁和引用能让设定在生成前就核对，但生成后的身份、造型与空间一致性仍要逐镜检查——它提供的是可核对的约束，不是保证。
