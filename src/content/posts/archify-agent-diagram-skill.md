**Archify** 是一个开源的 agent skill（画图技能）。装进 Claude Code、Codex CLI、Cursor、OpenCode 这类编程助手之后，你描述一个系统，或者让它读一个仓库，它会产出一张可交互的架构图。产物是单个 HTML 文件，浏览器打开就能点，看图的人不用装环境。[仓库](https://github.com/tt-a1i/archify)

它适合的场合很具体：写设计文档、合并前做架构评审、向同事解释一个陌生仓库的运行时结构。

<!--more-->

## 和让模型直接写 Mermaid 的差别

Mermaid 也能修改和检查文本图定义；这里要比较的不是「能不能改」，而是有没有为助手准备一套从结构描述、局部修改到交付检查的完整流程。

Archify 在中间加了一层：助手先写一份带类型的 JSON，再由随技能装的 Node 渲染器编译成自包含的 HTML/SVG。这一层带来两个实际好处，也是它区别于「一次性出图」的地方。

**修改有稳定的落点。** 你说「加上认证」「高亮缓存未命中的那条路径」「换浅色主题」，助手改的是 JSON 源文件，再重新渲染。期望是只动指定部分，实际仍要检查前后差异，不能默认模型不会顺手改掉别处。

**交付前检查结构与布局。** 流程要求检查数据格式、连线、标签与避让关系，通过后才替换上一张图。失败时把问题定位到具体对象，让助手针对性修改，而不是整张重画。

保留源文件与已确认版本的意义，是后续能继续改、也能退回上一张，不用每次从一张截图重新猜。

## 能画什么

先按要回答的问题选图：系统由哪些部分组成，用架构图；一次请求怎样经过服务，用时序图；数据去了哪里，用数据流图；任务如何重试和结束，用生命周期图。表关系、层级与时间线也有对应类型，不必把所有信息挤进一张架构图。

拿不准用哪种，先让内置的场景向导给建议——它只推荐类型和写法，不替你出图。

## 一个具体的用法

安装是一条命令，本机要有 Node.js 18+：

```bash
npx skills add tt-a1i/archify -g
```

然后给它一句带结构的话：画一次 Web 请求——浏览器调 API，API 查 Redis，未命中就查 PostgreSQL 并把结果写回缓存。之后再叠「加上认证」「高亮未命中的那条路径」这类调整。

让它读真实仓库时，提示词要把范围限死，否则模型会越画越密。仓库推荐的写法是：画一张高层运行时架构图，8–12 个核心组件、一条主路径、外部依赖和信任边界，细节放进卡片而不是继续加连线。

打开产物后，可以搜索节点、追踪路径，再导出用于文档的图片。做改动评审时，还能比较前后快照里的结构变化；这种比较说明的是增删与移动，不自动证明影响范围或风险。

## 边界

- **开源单仓库，MIT 许可。** 官网 archify.si 放文档和示例；同名的第三方在线服务和付费计划由各自运营方负责，不代表项目本身。
- **不是通用画图工具。** 自动解析 Mermaid、通用自动布局、托管分享、所见即所得编辑都不在范围内；Mermaid 只作为拓扑输入被读懂，再由助手重写成 JSON，不做机械渲染。
- **校验通过不等于好看。** 自动关卡保证的是 schema、布局和交互契约，视觉质量还得人看；时间线和瀑布图里的时间值若不是来自日志或追踪，会标成示意而非实测。
- **联网检查可选。** 更新提示只请求一份固定清单，不下载不安装也不上报项目数据，可以用环境变量彻底关掉。
