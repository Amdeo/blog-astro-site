**TRAE** 是字节跳动的 AI 编程客户端。TraeWork 与 TraeCode 合并后，偏任务交付的工作台和偏编码的编辑器放进同一个应用，用 Agent 模式与 IDE 模式区分。[产品迁移说明](https://docs.trae.cn/ide_traework-to-traecode-data-migration)

合并解决的是接力问题：以前用 TraeWork 拆需求、写文档、生成内容，再打开另一个客户端改代码，中间要重新交代项目和改过什么。现在这两段在同一个任务里。

<!--more-->

## 值得记的一点：上下文跟着任务走

合并最实在的收益在这里，而不在功能数量。

要看的是任务能否在两种模式间接续，而不是按钮有没有摆在同一窗口。比如先让 Agent 做出一个页面，再切 IDE 改字段校验，回来继续测试时应当能利用已有项目与任务上下文；具体接续程度仍要在当前版本里用一个小任务确认。

差别在于过去两个客户端各有各的会话和工作区，交接靠人复述；现在切的是**视图**，任务本身没断。所以典型路径是：在 Agent 模式里把想法推成能打开的产物，需要逐行改时切 IDE 抠细节，改完切回来继续测和交付。

## 两种模式各接什么活

- **Agent 模式**：从想法拆解到交付结果。新手可以一步步做出 Demo；专业开发者可以在一个窗口里管多个项目，按任务分配 Agent 并行推进，实时看进度，也可以在多目录下发本地任务或接 SSH 远程环境。
- **IDE 模式**：单项目深度编辑与调试，保留完整的智能开发环境。

官方对两者的定位就是这条分工，但「能做到什么程度」跟版本和放量有关，发布时的宣传不等于当下每个账号都有的能力。

围绕两种模式还有一条统一工作流：自动化任务（定期整理进度、跑固定检查、汇总测试、生成报告）、模板库、我的助理、我的产物。桌面、Web、移动三端共用同一套任务——电脑上起头，手机上看进度补要求，回桌面继续。

## 第一次用，先定住这三件事

1. **先绑工作目录，再发任务。** 不要只在提示词里写一个路径。先选好实际工作区，再检查产物究竟保存在哪里，避免做完后才去临时目录找文件。
2. **一条提示词写清目标、交付物形态和验收口径。** 比如「产出可直接双击打开的 index.html，零外部依赖」，比「做个工时记录器」好验收。
3. **审批先用「手动审批」。** Agent 碰到工作目录之外的东西会弹授权，跑熟再放宽。判断结果看真实文件路径和任务状态，不要只看对话里的总结。

模板库的「做同款」比想象中重：点进去回到 Agent 首页，输入框里会同时填好指令、技能和素材，不是只给一段提示词。不过精选位的模板偏办公经营报告，真要写代码，更实用的入口还是把目标讲清楚。

## 自动化之前，先跑一次完整交付

想把任务设成定时执行，先手动完成一轮：确认工作目录、运行环境、输出位置与权限，把结果打开检查，而不是只看「任务完成」。产物面板和实际磁盘文件也要分开核对，不能只依赖其中一个入口。

本地、云端与远程环境不是同一个文件系统。模型说保存到某个路径时，还要知道那个路径属于哪台机器；任务被权限拦住，就按授权流程处理，不为了省一次确认而直接放开所有权限。

## 升级的人注意一件事

装过 TraeWork 的走客户端里的升级提示。升级会顺带卸载 TraeWork，勾了「删除本地数据」会连日志和 AI 数据一起删，先确认要迁移什么。

我更看重这种合并能否减少交接：任务目标、目录、变更和验收结果能一起延续，才是真正省掉重复说明。选主力工具时，用自己的真实小任务走一遍，比看功能列表更有判断力。
