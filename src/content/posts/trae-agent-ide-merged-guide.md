TRAE 是字节跳动的 AI 编程工具。2026 年 10 月，它把两个客户端合成了一个：面向专业开发的 TraeCode 和偏办公与任务交付的 TraeWork 融合升级为「全新的 TRAE」，一个入口里同时装着 Agent 模式和 IDE 模式。[1]

如果你之前在两者之间来回切换——用 TraeWork 拆需求、写文档、生成内容，再打开 TraeCode 改代码——新版就是来接管这段接力的。[1] 它可能替你解决两类事：用一句话把想法做成能点开的 Demo，或者在同一个工作台里跨项目调度多个 Agent，边推进边看进度。[1][6] 需要的话还有另外两种形态：嵌进主流 IDE 的 TRAE Plugin，和能在终端或 CI/CD 里跑命令行任务的 TRAE CLI，二者与客户端同在一个产品矩阵里。[2]

有一个时间点需要先记住：TraeWork 的过渡期在 2026 年 10 月 23 日结束，届时它停止服务，未完成升级的用户无法继续使用。[1]

<!--more-->

## 合并之后，一个客户端里有两套工作方式

官方对两种模式的分工写得很清楚。[1]

| 模式 | 适合什么 | 官方定位 |
| --- | --- | --- |
| Agent 模式 | 从想法拆解到交付结果；跨项目调度多个 Agent 并行推进 | 新手可以一步步做出 Demo，专业开发者当成开发工作台 [1] |
| IDE 模式 | 单项目深度代码编辑与精细调试 | 保留完整智能开发环境 [1] |

切换不是换一个窗口。一份公开的社区实测（Trae CN 3.4.2、macOS）记录了这件事：作者在 Agent 窗口点右上角的「IDE」按钮，等十几秒切过去，结论是「上下文是跟着任务走的，不是跟着窗口走的」，不用重新解释这个项目在干什么、刚才改过什么，也不用重新索引。[7] 这大概是合并相对「两个客户端各干各的」最实在的一处收益。[7]

与两种模式并行的还有一条统一工作流：自动化任务、模板库、我的助理和我的产物都进了同一个客户端。[1] 自动化任务把定期整理项目进度、运行固定检查、汇总测试结果、生成报告这类重复流程交给 Agent 持续执行；模板库让产品方案、页面搭建、数据分析、技术文档这类高频任务从模板起步；我的产物把代码变更、HTML、PPT、Word、报告统一收进一个地方，不用再翻聊天记录找结果。[1]

三端也打通了：在电脑上启动任务，在移动端查看进度、补充要求，再回到桌面继续深入开发，项目、任务和产物沿用同一套工作流。[1]

## 视频里那条路径：四步做出一个「AI 股神」工作台

抖音作者「程序员三千」用新版 TRAE 从零做了一个量化投研工作台。视频里的成品侧栏有市场看板、策略选股、回测研究、因子挖掘、监控中心、市场环境、AI 多智能体七个模块；最后跑起来的是多 Agent 投研流水线，分析师并行出结论，多空研究员辩论两轮。[8] 这条路径值得看的不是股票，而是它把「找料 → 写需求 → 做设计 → 出成品」串在了同一个工作台里。[8]

第一步是提取素材。他没有手动下载仓库，而是在任务里调用 GitHub 相关插件，把几个开源项目的核心提示词与功能模块提取出来。官方对 GitHub 的支持走外部应用授权：在设置里连接账号之后，可以发起并检查 PR，但有一条硬限制——仅云端任务支持 GitHub 应用。[5]

第二步把素材变成 PRD。调用产品经理 Agent，输入整理好的提示词，输出需求背景、目标定位、用户场景、产品架构，以及给设计和开发 Agent 的说明。[8] 视频里这一步是分钟级的（约十七分钟），文档落到 12 章。[8]

第三步做原型。两条路：直接用模板库里的现成模板，或者把喜欢的截图丢给设计 Agent 当参考，再补一句「样式参考截图、功能参考 PRD」。[8] 模板库的「做同款」不只是给一段提示词——实测作者点进去后，输入框里同时出现了指令、技能和示例数据三样东西。[7]

第四步才是写代码和交付。一句提示词让开发 Agent 出第一版，不满意就再改几轮；需要抠代码细节时切到 IDE 模式手动修改，改完回到 Agent 模式继续测试交付。[8] 视频里原型任务的耗时是 32 分钟出头，产出的是一份纯静态、零外部依赖、可以双击打开的 index.html。[8]

这个成品页面自己标着「9 Agent · 流水线 · 可追溯 · 可归因 · 可验证」，同时挂着免责声明：仅供研究参考，不构成投资建议，不接入交易通道、不自动执行。[8] 它是作者的个人项目，不是 TRAE 官方范例。同样是投研工具方向，本站之前整理过 Easy Stock，那篇讲的是现成应用怎么用，这篇讲的是用 Agent 把它做出来的过程。

## 容易踩到的四个地方

工作目录不绑，文件会落到临时目录。实测里最值得记住的一条：提示词里写了目标路径，但如果没绑定工作目录，任务实际会落在客户端自己的临时目录下——提示词里的路径不会覆盖它。[7] 想让产物待在预期位置，先绑工作目录，或者在对话里把工作区换过去。[7]

「我的产物」的收录范围，文档和实测有落差。官方说代码变更、HTML、PPT、报告等内容都会统一进入「我的产物」；[1] 但上面那份实测里，两个本地任务（绑定与不绑定工作目录各一个）都跑完了、文件也确实落在磁盘上，「我的产物 → 本地」两次都是「还没有文件」。[7] 这是单个版本、单个账号下的观察，可能是延迟，也可能只收云端任务，至少在这个版本上，别把「我的产物」当成文件管理的唯一入口。[7]

自动化任务的字段对不上文档。官方文档说手动新建要配置任务名称、触发时间、任务内容、运行模式（Work / Code）、运行环境（云端 / 本地）、输出内容的存储位置；[3] 实测作者把三种环境都切过一遍，表单里没有「输出内容的存储位置」这一项。[7] 另外任务一旦创建，运行模式、运行环境和输出位置都不能再改，所以建之前要想清楚。[3]

模板与沙箱的默认值也要有预期。模板库分了 9 个分类，精选位当前 9 个模板清一色是办公经营报告类，实测作者的原话是「一个面向写代码、做工程的模板都没有」，真要写代码，更实用的入口还是把目标讲清楚。[7] 审批方面，实测环境的沙箱默认文件系统只读、被拦住时走「申请权限后重试」，网络默认放开；插件和扩展可以从 TRAE 扩展市场、VS Code 扩展市场，或者本地 .vsix 文件导入。[4][7]

## 想试的话，按这个顺序走

1. 下载安装（国内版 trae.cn，国际版 trae.ai），登录后先看一眼界面：左边是「新建任务 / 插件市场 / 我的助理 / 自动化 / 模板库 / 我的产物 / 项目」，右上角有一个单独的 IDE 按钮，这就是合并后的样子。[7]
2. 导入或新建项目之后先绑定工作目录，再发第一个任务：把目标、交付物形态（比如「可直接双击打开的 index.html」）和验收口径写进同一条提示词。[7]
3. 审批模式按需要选。手动审批会在 Agent 触碰工作目录之外的东西时弹出授权，适合第一次跑；跑熟之后再放宽。[7]
4. 用 Agent 模式推进多步任务，需要逐行改代码时切到 IDE 模式，改完切回来继续，切之前不用重新描述项目。[1][7]
5. 判断结果的方法：回复头部会自己报任务耗时和动作数（读了几个文件、执行了几条命令），产物则要看真实的文件路径，而不是只看对话里的总结。[7]
6. 老用户如果装的还是 TraeWork，走客户端里的升级提示。注意勾选项：升级会顺带卸载 TraeWork，勾了「删除本地数据」就会连日志和 AI 数据一起删掉，先确认要迁移的内容。[1]

至于要不要把它当主力工具，那是另一回事。本文没有在本机安装运行 TRAE：上面的内容来自官方文档、视频演示和一份公开的社区实测报告；视频里也提到新版本正在逐步放量，同一功能在不同版本上的表现可能不一样。[7][8]
