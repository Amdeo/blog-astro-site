WorkBuddy（腾讯 WorkBuddy）是一个桌面 AI 工作台：用一句话说需求，它自己拆步骤、读写你授权的本地文件，交出一份能验收的结果。它面向的不是开发者，而是每天在处理 Word、Excel、PPT 和文档的职场角色。

Skill 是它扩展能力的方式。一个技能本质就是个文件夹，核心是一份 `SKILL.md`：头部写「这个技能做什么、什么时候用」，正文写「按什么流程做」，需要时再带上脚本、参考文档和模板。装一个技能，等于把一段固定的做事流程交给它，同类任务以后不用每次重新解释。

<!--more-->

## 为什么「描述」那一行最关键

一个技能最少只要一个 `SKILL.md`，其余目录都可以没有。约定用这几个目录装附属内容：`scripts/` 放需要确定性执行的脚本，`references/` 放按需查阅的文档，`assets/` 放模板、字体、图标这类输出资源。

头部只有两个必填字段：`name`（技能标识，最多 64 个字符，只允许小写字母、数字和连字符，必须和所在目录同名）和 `description`（最多 1024 个字符，要同时写清做什么、什么时候用）。

`description` 是助手识别使用时机的重要线索。按渐进式加载的思路，先提供技能名与简介，选中后再读正文，参考资料与脚本按需取用。触发还取决于宿主与模型，不能只写一大段正文，却没在简介里说明它适合什么任务。

## 装进来有哪几个入口

技能市场分上下两半：上半是已经装在本地、可以直接在对话里调用的技能，下半是推荐技能，按需一键安装。

添加技能有三条路：上传本地技能包、按任务描述让它「查找技能」、按描述直接「创建技能」；不需要的可以在本机卸载。自己建不用写代码，把「要什么能力、什么情况触发、输出成什么样」说清楚就行，执行完在技能栏的「已安装」里能看到。官方给的三条建议也适用：第一个技能只解决一个明确问题、把触发条件写清楚、从最高频的重复动作开始沉淀。

## 8 个推荐技能，各自替你做哪一步

可以从下面八类重复工作里挑需要的能力。它们不是 WorkBuddy 默认内置的固定套装，同名技能也未必来自同一作者，安装时要核对发布页与实际支持的环境。

| 技能 | 替你做的 | 什么时候想起来用它 |
| --- | --- | --- |
| Find Skill（智能找技能） | 按任务描述去找合适的技能 | 不知道该装什么 |
| 办公全家桶（Word / Excel / PPT / PDF） | 写文稿、搭表格、做汇报、读和转 PDF | 日常办公的重复活 |
| Self Improving（自我改进） | 把纠正过的地方记下来 | 同类任务反复踩同一个坑 |
| Memory Setup（长期记忆） | 记住习惯和偏好 | 每开新会话都要从头交代 |
| Summarize（内容总结） | 长视频、长文章提炼核心观点 | 看不完又想知道讲了什么 |
| Skill Creator（创建新技能） | 用大白话把需求变成能用的技能 | 想自己做一个 |
| Humanizer（去 AI 味） | 把生硬的句子调顺 | 写文案、做内容 |
| Video Downloader（视频下载） | 获取有权访问且允许保存的视频 | 收集参考素材 |

办公那一类值得说清来历：Anthropic 的[公开技能仓库](https://github.com/anthropics/skills)里有同类的开源实现（`skills/docx`、`skills/pdf`、`skills/pptx`、`skills/xlsx`），它们是为 Claude 文档能力提供底层支持的技能，可以当作「复杂技能怎么写脚本和参考文档」的样例。那是 Anthropic 的技能，不等于 WorkBuddy 自带，装之前还是以技能市场里看到的为准。

Self Improving 的常见实现是：把命令失败、用户纠正、能力缺失、知识过时这些情况按类记到 `.learnings/` 下的 markdown 文件，反复出现的结论再提升到工作区记忆文件（比如 `AGENTS.md`）。它附带的可选 hook 只负责提醒和捕获，不强制这套流程，也不会回头复核记下的结论是否成立。「记下来」和「下次一定照做」是两件事。

## 自己写一个最小的

```markdown
---
name: meeting-notes
description: 把会议记录整理成结构化纪要与待办清单。当用户说「整理会议纪要」「从这段记录里提取待办」时触发。
---

## 工作流程
1. 提取会议主题、时间、参与人。
2. 按「讨论 → 决议 → 待办」三段输出，待办带上负责人与截止日期。
3. 输出为 Markdown 文件，写入用户指定目录。
```

把示例放在 `meeting-notes/SKILL.md`，再按 [Agent Skills 规范](https://agentskills.io/specification)准备参考校验工具。`skills-ref validate ./meeting-notes` 可检查头部字段和目录命名；格式通过之后，还要拿几条真实请求测试触发与结果。

想认真迭代一个技能，可以装 Anthropic 官方的元技能 `skill-creator`：它把「想清楚做什么 → 写一版草稿 → 准备几条测试提示词跑一遍 → 按评测结果改写 → 打包交付」固定成循环。带评测的迭代比反复凭感觉改 `description` 靠谱，因为触发准不准本身可以量化。

## 要自己把关的地方

技能是别人写的代码。能带 `scripts/` 就说明它可能真在你机器上跑东西，装之前看一眼来源和作者。官方仓库对自家技能的提醒同样适用于第三方：这些技能用于演示和教学，实际拿到的行为可能不同，用在关键任务前要在自己的环境里完整测过。

社区里出现同名技能时，以技能市场里那个作者为准，别把别处的实现当成同一个。
