`gh` 和 `tea` 都是代码托管平台的命令行工具：前者用于 GitHub，后者是 Gitea 的官方工具。[1][3] 装好并连接账号后，你可以在终端里查看项目问题、处理合并请求和管理发布，不必每次切到网页操作。

如果你平时已经在终端里写代码，却还要不断打开浏览器查“有没有新的问题、谁提交了修改”，这类工具能把一部分工作留在同一个窗口里。

**它们不是 Git 的替代品。Git 管理代码版本，gh 和 tea 负责跟托管平台打交道。** 先分清这一点，后面的命令就容易理解了。

<!--more-->

## 先分清三个东西

这些名字经常一起出现，但负责的事情不同：

| 名称 | 负责什么 |
| --- | --- |
| Git | 记录代码修改、提交和分支，是版本管理工具 |
| GitHub、Gitea | 托管代码仓库，并提供问题跟踪、修改评审等协作功能的平台 |
| gh、tea | 用命令访问相应平台功能的工具，分别连接 GitHub、Gitea |

例如，你用 Git 保存了一次代码修改，再把它推到托管平台。别人要讨论这次修改、提出建议、决定是否合并，这些平台上的工作就可以由 gh 或 tea 来辅助处理。

GitHub 和 Gitea 是不同的平台，因此不是在两个工具里任选一个就行。你的项目在哪个平台，就先使用对应工具。

## 用一次查看修改的任务认识它

假设你正在维护一个项目，想知道有哪些修改正在等待处理。

你可以打开网站进入项目，也可以在终端里列出 PR。PR 是 Pull Request，通常译为拉取请求；可以把它理解为“请把我这个分支的改动合进去”的提议。它通常带着修改说明、代码差异、讨论和检查结果。

处理过程大致是：

```text
列出待处理的修改 → 选择一条 → 阅读说明与差异 → 决定如何处理
```

命令行工具把网页上的部分操作变成命令。它不会替你判断修改是否正确，也不会消除代码评审这一步。

## 除了 PR，还可以做什么

两类工具都围绕平台日常工作提供入口，例如查看和管理 Issue、仓库与发布版本。[1] Issue 是项目里的问题记录，可以是一份 bug 报告，也可以是一条需求。Release 则是发布给使用者的某个版本及其说明和附件。

它们也有自动化任务相关功能。比如代码推送后，平台自动运行测试或构建；你可能希望在终端里查看任务进度。能否查询到这些结果，还取决于平台是否提供并启用了相应功能，不是装上命令就凭空拥有一套持续集成服务。

开始时不必把所有子命令都学完。先掌握“列出一组记录、读其中一条”，就能覆盖不少日常查询。

## 先做一次只查看、不修改的尝试

前提是已安装工具，并按其官方说明连接账号；使用 Gitea 时还要配置自己的服务器地址。先用自己有权查看的项目试，不需要为了入门就给账号开放所有权限。

下面的 `owner/repo` 要替换成实际的仓库名，例如“仓库拥有者/项目名”；`12` 要替换成真实存在的 PR 编号。这些是命令用法示例，不是本文已经向账号发出的查询。

GitHub 用 gh：

```bash
# 列出开放的 PR
gh pr list --repo owner/repo --state open --limit 20

# 查看其中一条的说明
gh pr view 12 --repo owner/repo
```

Gitea 用 tea，下面按 tea 0.16.0 的命令形式书写。`work` 是读者已经配置的目标服务器登录名称，不是密码：

```bash
tea pr list --repo owner/repo --login work --state open --limit 20
tea pr --repo owner/repo --login work --comments=false 12
```

查询后先确认读到的是目标仓库和对应 PR。没有开放 PR 时，空列表也可能是正常结果。GitHub 的详情命令有 `view`，而这里的 tea 直接在 `pr` 后指定编号；两者不能简单互换工具名。[3]

## 什么情况下值得用

如果你大部分时间在终端里工作，希望少切几次窗口，或者准备把重复查询写进脚本，命令行工具很合适。给能运行终端命令的 AI 助手使用时，它也能获得较明确的操作入口。

如果只是偶尔查看一个项目，网页通常已经足够，不必为了用命令行再增加学习成本。

后续再考虑创建 PR、评论、合并和发布。这些会真正修改平台状态，应当在看懂目标和权限之后再做，尤其不要让自动化程序把“能读取”理解为“获准合并”。

## 两个平台都用，怎么安排

保留两套工具即可：GitHub 工作交给 gh，Gitea 工作交给 tea。自己写脚本时，可以再整理统一的输入输出，但不要假定两个平台的字段和参数相同。

你一开始需要记住的不是一张命令对照表，而是：**Git 负责代码版本，平台负责协作，gh 和 tea 让你用命令访问对应平台。**

<details>
<summary>示例版本与进一步自动化时的注意事项</summary>

- 本文核对过 tea 0.16.0、gh 2.102.0 的版本与帮助；仓库查询示例没有进行端到端执行，也没有修改账号配置。
- Tea 的 main 文档已包含 1.0 的迁移说明，不能直接当作 0.16.0 的用法。[2] 安装不同版本后，应重新看本机帮助。
- 自动汇总全部 PR 时，要另行处理分页和状态：本版 tea 的 limit 指每页数量，gh 则是最多获取数量；关闭也不自动等于已合并。

</details>
