huashu-art-motion 是花叔开源的一个 agent skill（技能包）：把它装到 Claude Code、Codex、Cursor 这类会写代码的编程助手旁边，你就可以用一句需求换一段动画——「复刻这段参考动画」「做个梵高那种风格的短片」「把我这段口播配成白板解说动画」，助手写代码把画面画出来，渲染成 MP4。[1][2]

它和「让 AI 生成视频」是两条路：画面不是生成模型直接吐出的像素，而是由代码画出来的——形状、笔触、镜头和节拍都写在参数里，随机数用固定种子，所以同一时刻渲两次逐像素一致。[2] 改一版、重渲、和参考片并排对比，都是在命令行里完成的事。[1]

<!--more-->

## 主题概览

仓库 2026 年 10 月初开源，MIT 许可，主体是 JavaScript 代码加一批中文方法文档；查询当日（2026-10-19）约 4351 颗星、469 个 fork。[3]

它要解决的问题很具体：动画的「讲法」平时藏在剪辑和动效软件的手工操作里，换一个题材就得重做一遍。huashu-art-motion 把其中可复用的部分固定下来——每种艺术风格的配方卡（参数、母题动作、签名转场，以及这一种风格的当前短板）、一套可以整个复制到项目里的渲染工程、还有交付前自动跑的检查脚本。[1][2]

适合做口播、科普、产品视频的人，也适合想让助手直接产出动画素材的开发者；前提是你手边有一个会写代码的编程助手。[2]

## 核心技术

### 一段参考动画怎么变成「能写代码的地图」

它最核心的动作是复刻，流程写成三步：拆解 → 机制 → 代码复刻。[2] 拆解脚本把参考动画拆成一张能写代码的地图——量出转场在哪、拟合节拍网格、看每一段哪里在动（运动热图）；拿到这些测量值之后，助手再按机制用代码把画面重新画一遍，而不是把原片裁一裁拼起来。[1][2] 视频横幅里那句「形成一份代码图纸」，说的就是这一步。[5]

### 画是活的，不是一张图切一张图

README 里留了这段经历的原始版本：第一版复刻做的是「一张张画之间做转场」，被作者否掉了，理由是一个时代可能只有一秒，但画里的元素本来是流动的；于是改成先量化、再用代码一层层把画画出来。[1] 做法上对应的是「一帧先行」——先设计一帧，确认这一帧立得住，再让它动起来。[1]

让画面动起来靠的是工程里的场景代码与参数化片段：风格场景用 Canvas 画（梵高的笔触、像素方块、水墨晕染都在里面），解说类画面则喂一份 JSON spec 按帧输出，单个参数化片段最多撑 8 秒，超了拆成几镜。[2]

### 画面里要有人，就交给生图模型

代码不画人脸。需要真人、角色或吉祥物出镜时走分工路线：人交给生图模型出帧，代码负责合成、换帧和材质；没有生图能力时就只出手和背影。[1][2]

### 交付前有三道检查

这是它比较少见的一面：把「别交付烂片」写成了脚本。渲染完先跑 `qa.py`，量稳定、效率、动感、流畅以及文字框景线索；再派一个没参与制作的 agent 只看成片挑问题；最后由 `deliver.py` 交付，它先过门禁 `film_gate.py`——快速运动帧占比低于 0.035 直接红灯，脚本不复制成片、非零退出，低于 0.06 记黄灯。门禁还会查成片中段连续 0.3 秒以上的空画面，以及蓝紫底画面是否超过全片 30%。[1][2] 过了才复制成片并写交付说明，说明里的事实段由脚本写，被改动会被 `deliver.py --verify` 查出来。[2]

## 实践应用

### 装与跑

安装是一行命令：`npx skills add alchaincyf/huashu-art-motion`。[1] 运行依赖 uv、ffmpeg 和 Playwright 的 Chromium，第一次跑要装浏览器。[1] README 给的两条试渲染命令是：

```bash
uv run --with playwright python scripts/engine/render.py --solo 09_postimp --stills 0.3 --out 试渲
uv run --with playwright python scripts/engine/render.py --spec scripts/engine/examples/t3_finance_chart.json --out 财经图表.mp4
```

第一条抽梵高那一段的一帧，第二条按示例 spec 出一段财经图表片段。[1] 这两条命令抄自仓库说明，本文没有在本机执行，只核对到它们与仓库里的目录结构一致。[1]

### 作者列的「六种做坏方式」

文档里有一份反面清单，等于作者的验收标准：翻页式 PPT（固定页眉、要点逐条淡入、结尾落回金句卡）、照搬示范片里的构图和角色、抽象概念只写成字和图标、大面积的死背景或空画面、手里有真实素材却用代码去画、以及一眼 AI 味的蓝紫渐变和每镜换画风。[2] 这些问题里有一半能被打分脚本量出来，另一半要靠抽帧对照和按正常速度看一遍成片。[2]

## 使用边界

**模型能力决定走哪条路。** SKILL.md 自己分了档：Opus 5.5 或更强的模型走「开阔档」，路由表、库和渲染器都可以自己组合；其它模型走「轨道档」，只走一条固定路径——先照模板写镜头表、过 `storyboard_lint` 的检查、再逐镜渲染。[2] 这是项目总结出来的经验口径，不是装上就必然达到的保证。[2]

**画风数字的口径在变。** 视频横幅写「35 种动画画风＋8 种解说风格」[5]，仓库当前 README 的清单表写 53 张配方卡、53 个场景代码，同一份 README 的功能表又写「36 张风格配方卡当起点」，SKILL.md 的自述是「36 种既有实做风格＋16 种可迁移研究配方」、9 种解说语法（8 种可按口播参数渲片段）。[1][2] 这几处口径并不完全一致，引用时带上查询时间更稳妥：本节数字查于 2026-10-19，仓库 main 对应提交 8a0d7d7。[4]

**有些素材要自备。** 口播整片的参考代码是代码快照，要自己准备角色和音频；要让画面里出现真人，要么有角色素材，要么给助手接上生图能力。[1]

**许可有例外。** 代码和文档是 MIT，但花叔的卡通形象与角色帧（包括总览图、示范视频里出现的同一形象）只允许用于这个 skill 的示范；笔顺衍生数据沿用 Arphic Public License，仓库内字体沿用各自的 OFL 许可；《Clawd 博物馆奇妙夜》是非官方同人示范，Clawd 形象权利归 Anthropic，不随 MIT 授权。[1]

**验证范围也是它自己写的。** 仓库的兼容性说明写的是「三家安装重装通过；Codex 在线回归通过，Claude Code/Kimi 在线回归受测试账户条件阻塞，待补验」。[1] 整套东西的起点，是作者复刻另一支 15 秒短片《Art History Speedrun》的过程，当时把「积累经验」也写进了 skill——哪些做法被证明有效、每种风格的坑和短板，都留在仓库里。[1]
