[huashu-art-motion](https://github.com/alchaincyf/huashu-art-motion) 是花叔开源的动画制作技能，用来指导 Claude Code、Codex、Cursor 这类编程助手拆解参考、编排镜头和生成动画代码。适合尝试艺术风格短片、参考动画复刻或白板解说，不是一个点下按钮就完成制作的视频网站。

<!--more-->

这条路线的重点是画面由代码绘制。形状、笔触、镜头和节拍有明确参数；按时间与固定随机种子绘制后，可以反复对照同一时刻，改文案或节奏时不必把整段画面重新抽一遍。

## 复刻的三步

核心动作是复刻，流程是拆解 → 机制 → 代码复刻。拆解脚本把参考片变成一张能写代码的地图：量出转场在哪、拟合节拍网格、看每一段哪里在动。拿到测量值之后，再按机制用代码把画面重新画一遍，而不是把原片裁一裁拼起来。

一个值得记的区别：几张画之间加转场，和画里的元素真的在运动，是两回事。先把一帧的主体、层次与笔触做好，再决定哪些元素怎样运动，比先堆整条时间线更容易发现问题。这就是「一帧先行」的用法。

## 画是活的，人脸不是代码画的

风格场景用 Canvas 画，笔触、像素方块、水墨晕染都在里面；解说类画面喂一份 JSON spec 按帧输出，单个参数化片段最多撑 8 秒，超了就拆成几镜。

代码不画人脸。需要真人、角色或吉祥物出镜时走分工：人交给生图模型出帧，代码负责合成、换帧和材质；没有生图能力就只出手和背影。

## 把「别交付烂片」写成阈值

它把交付前的检查分成自动检测、独立审片和最终门禁：检测画面是否缺少运动、是否有异常空白与文字问题，再让没参与制作的助手看成片挑毛病，不只相信制作者自己的总结。

值得借用的是把模糊评价变成可检查的问题。「像翻页 PPT」可以具体到镜头内部几乎没有运动；「节奏不舒服」可以检查文字停留与转场；「风格乱」则回看色彩和笔触是否一致。自动门禁能挡一部分问题，但不能替代人看画面。

## 装一个试试

```bash
npx skills add alchaincyf/huashu-art-motion
```

运行需要 uv、ffmpeg 和 Playwright 的 Chromium，具体准备按仓库说明完成。第一次不要直接做整片，可以要求助手先给一个风格帧，再做一个短镜头，确认效果后继续。

例如做艺术画作主题的片头，先检查静帧里主体是否清楚、笔触是否像目标风格，再让笔触逐步出现或推动镜头。只有镜头在推、画面内容完全不动时，要重新考虑它究竟是在做动画，还是在播放一张图片。

## 边界

- 不同模型对代码、审美和长流程的处理能力有差异，先用一个小镜头确认它能否按要求完成，再扩展制作范围。
- 口播整片的参考代码是代码快照，角色和音频要自备。
