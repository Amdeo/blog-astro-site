[Prompt Optimizer](https://prompt.always200.com)（提示词优化器）是一个开源工具，做的事很直白：把你随手写的提示词贴进去，用它调用你自己配置的大模型改写一遍，还你一段结构更完整、约束更明确的提示词文本。打开网页版就能试，数据存在浏览器本地。

优化阶段只改提示词，不直接执行里面的任务；测试区域再用改写前后的提示词生成结果。除了网页版，还有桌面版、Chrome 插件、Docker 部署与 MCP 接口。

什么时候用得上：经常和模型对话却总觉得「说得不够清楚」，或者要写系统提示词、角色卡这类长指令。只想让模型直接解决问题、对提示词本身没兴趣的话，它帮不上忙。

<!--more-->

## 改写是怎么发生的

内置的「优化模板」是一段指导改写的提示词，再把你提供的文本一起发给模型。不同模板会强调角色、目标、约束或工作步骤，但结构更完整不等于效果自动更好。

比如原来只写「帮我总结周报」，可以补上要看哪些材料、按什么栏目组织、缺信息怎么处理，以及不能编造完成进度。若原提示词带 `{{项目名}}` 这类变量，占位符应原样保留，不要在改写时替换成某个具体项目。

模板也不是一套通吃，而是按工作区分别提供：系统提示词、用户提示词、变量、多消息、文生图、图生图各有对应模板，内置的还能复制一份改成自己的。

任务本身不清楚时，先补目标和资料，再谈措辞。它可以帮助整理要求，但不能凭空知道你没提供的背景。

## 怎么判断改完真的更好

这是它比「在聊天框里让模型帮我改一下」更值得用的地方：左边改，右边跑。

左边的分析只看提示词本身——目标是否清楚、约束是否完整。右边拿真实输出来比，有两种判断方式：结果评估看某一列输出本身合不合格；对比评估看多列之间谁更好、差在哪里，比如「原始 vs 优化后」「同一条提示词换不同模型」。

最低要求并不高：在同一个模型下分别跑原始版和优化后的版本，比较两次真实输出，一个文本模型就够。这一步比读着改写后的文字凭感觉判断可靠得多。

不满意就给出具体改进方向，再优化一轮。最好保存原始版与采用版本：看它是否补齐了必要条件，还是只把一句话扩成了几段漂亮的套话。换模型后也重新比较，不默认上一轮的结论仍成立。

## 数据在哪，代价是什么

网页版是前端应用，设置与记录保存在当前浏览器中，优化请求则发给你配置的模型服务商。数据留在浏览器，不代表提示词内容不会发送给模型；不要把敏感材料直接当测试文本。

网页版能否直连接口，受服务商的跨域配置与浏览器安全策略限制。要接本地模型或内网服务，优先考虑桌面版。自建公开站点时，别用 `VITE_*` 环境变量预置密钥，这些值会进入前端构建产物。

| 形态 | 最适合 | 主要限制 |
| --- | --- | --- |
| 在线版 | 打开即用、跨设备临时用 | 受 CORS 与混合内容限制 |
| 桌面版 | 接本地模型、内网接口、长期使用 | 需安装并确认应用来源 |
| Chrome 插件 | 在浏览器里快速打开 | 轻量入口，没有右键菜单，也不回填网页输入框 |
| Docker | 自建服务，顺带提供 MCP 接口 | 需要自备 API 密钥 |

插件更接近快捷打开工具的入口，不要把它当成会自动改写所有网页输入框的增强插件。想接到其他助手，则可以使用 Docker 部署提供的 MCP 服务。

```bash
docker run -d -p 127.0.0.1:8081:80 --restart unless-stopped --name prompt-optimizer linshen/prompt-optimizer
```

这是本地部署示例，需要先准备 Docker，端口只绑定本机。启动后，MCP 地址是 `http://localhost:8081/mcp`，客户端和模型配置仍要自己完成。

## 一次完整用法

1. **配模型。** 右上角模型管理，填入一个可用模型的密钥（OpenAI、Gemini、DeepSeek 或任意 OpenAI 兼容接口），点测试连接确认通过再保存。
2. **改一轮。** 左侧贴入原始提示词，选好工作区（系统提示词 / 用户提示词）和模板，开始优化；不满意就继续优化，不必从头重写。
3. **验证。** 右侧用同一个模型分别执行原始版与优化版，先看单列的结果评估，再用对比评估总结差异，把有价值的建议应用回左侧工作区。


## 边界

**许可。** 项目采用 AGPL-3.0。修改后通过网络向用户提供服务时，要按许可履行提供相应源码等义务，自用与对外运营别混为一谈。

**它需要你的模型和额度。** 工具本身不提供模型，所有改写都消耗你配置的服务商配额，没有可用模型时界面再全也做不了优化。

改写后的提示词应当在真实任务上更有用，而不是单纯更长。最终看输出是否满足需求，不看角色标题和规则条目堆了多少。
